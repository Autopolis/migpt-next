# 小爱音箱 mini（LX01）实测结果

测试日期：2026-09-09。环境：macOS 26.6、Node.js 24、MiGPT-Next 1.3.2，模型为 `gpt-5.6-luna`。

以下结果来自一台 LX01 音箱，可作为配置参考；不同固件和网络环境仍需按[使用说明](../apps/local/README.md)完成测试。

| 能力 | 测试结果 | 使用说明 |
|---|---|---|
| 小米 passToken 登录 | 通过 | 密码登录触发额外验证后，使用浏览器登录凭证成功连接 |
| 设备列表 | 识别为 LX01 | 使用账号下实际设备的 miotDID |
| 云端对话记录 | 可读取 | 仍依赖小米云端接口 |
| MiNA TTS | 实际听到测试句和模型回答 | 默认使用该播报方式 |
| 暂停原生回答 | 请求被接受；复测听到一次完整回答 | 仍可能听到原生小爱先说出少量字词 |
| 播报状态 | MiNA：playing → idle；MIoT 4,1：1 → 0 | 约 16 秒的连续采样观察到播放和结束状态 |
| 远程唤醒 | MIoT 5,2 请求被接受 | 确认播报结束后调用 |
| 无前缀提问 | 成功收到问题并回答 | 不要求“请问” |
| 连续问答 | 开启口令、播报、唤醒、提问、模型回答和再次唤醒均有对应记录 | 由本地程序实现自动续听 |
| 响应耗时 | 数次测试约 4.4–7.1 秒 | 从程序收到问题到提交播报，不包含完整语音识别过程，也不是延迟分位数统计 |

这台音箱对原生“打开连续对话”口令回复“好像超出我的能力范围了”。本地助手支持相同口令，并通过播报状态检测和再次唤醒继续聆听。

## 尚未验证的范围

其他机型与固件、Windows、Linux、Docker、全天候运行、断网恢复、长期登录凭证刷新，以及多人或电视背景声环境。

如果基本问答能用，但连续对话不稳定，可以说“结束连续对话”，改为每轮手动唤醒；无需关闭普通模型问答。
